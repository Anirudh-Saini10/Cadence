RLS Policies (Security)

Row-Level Security enforces role access at the database layer:

  • goals — employees see their own; managers see direct reports'; admin sees all
  • checkins — same as goals
  • users — employees see self + manager; managers see team; admin sees all
  • audit_logs — admin read-only

UoM Scoring Formulas

Min      = (target / actual) * 100
capped   = min(score, 100)

Max      = (actual / target) * 100
capped   = min(score, 100)

Zero     = 100 - (actual / target * 100)
capped   = max(score, 0)

Timeline = (completed_milestones / total_milestones) * 100

Milestone = same as Timeline (binary gates)

Final weighted score per goal = (raw_score / 100) * weightage

API Layer

No custom backend. All data access via Supabase JS client:

supabase.from("goals").select("*").eq("employee_id", uid)
supabase.from("goals").update({ status: "submitted" }).eq("id", id)
supabase.auth.signInWithPassword({ email, password })

Caching Strategy

  • staleTime: 5000ms — data fresh for 5s after fetch, prevents re-render loops
  • gcTime: 5 minutes — inactive queries cached in background
  • Mutations: Call invalidateQueries() on success to force refresh
